# `/spreadsheet-reconciliation` — 財會級試算表雙向勾稽與差異歸因協議

結合會計工作底稿標準（Evidence Table）、試算表結構審計（`spreadsheet-auditor`）與月結差異拆解（`variance-analysis`），確保 Excel 母檔、DB 帳本與轉帳／傳票三方 100% 對平且零幻覺。

## 六大不可妥協鐵律

1. **No-Plug 原則（嚴禁自動塞差額抹平）**
   - 橫縱向或跨分頁勾稽只要差 **1 元（或超過允許四捨五入容差 `0`）**，必須立即硬阻斷匯入或回滾交易，產出逐筆差異報告；絕不可為了讓數字看起來相等而自行生成「調整項」。
2. **雙向對平（Cross-Footing）與子總帳檢核**
   - **橫向**：`底薪 + 各項加給 + 獎金 + 加班費 − 請假/代扣 − 勞健保自付 ＝ 應發 / 實發`。
   - **縱向**：全部明細列加總（跳過小計/合計列，並核對隱藏列處理口徑）必須等於總表合計欄。
   - **跨表**：如 `HR出勤計算` ⇄ `薪資明細主表` ⇄ `當月業績總覽` ⇄ 匯出之傳票借貸金額與銀行薪轉總額，必須兩兩互核。
3. **原始檔不可變與已核准歷史防覆寫鎖**
   - 上傳之 `.xlsx`/`.xlsm` 視同不可變原始憑證（僅讀不改）。
   - 已標記人工核准（`approved` / `paid`）或非自動匯入來源之歷史紀錄，新批次匯入**嚴禁靜默覆寫**。
4. **Evidence Table 證據溯源表（工程與內部稽核必備）**
   - 每個對帳結論必附結構化追溯來源：`來源檔案 | Sheet | 儲存格座標/範圍 | 計算公式 | 差額`。
   - **防幻覺原則**：欄位缺失、公式未快取且無法重算時，必須明確停止並回報「資料不足以判定」，嚴禁猜數填補。
5. **雙期變動歸因拆解（Flux / Variance Analysis）**
   - 比較本月 vs 上月差異時，不可只報總金額增減，必須拆成三大可解釋維度：
     - **人數變動（Volume）**：入離職人數增減導致的底薪與固定津貼變化。
     - **固定結構變動（Rate）**：調薪、年資或法定勞健保級距調整。
     - **浮動績效與工時（Mix）**：加班費、績效獎金、請假／缺勤扣款波動。
6. **對外隱私鎖 × `/eli5` 白話轉譯分工**
   - 內部核帳層保留精準座標與分毫差異；送進 LLM 或對外回覆／UI 副駕時，必須遮罩個人姓名與個人薪資，並交由 `/eli5` 轉為財務與管理層直覺可懂的業務說明。

## 標準對帳工作流

1. 先執行 `python .agents/skills/xlsx/scripts/xlsx_ingest_profiler.py <file>` 取得結構、隱藏列、合計列與公式健檢。
2. 確認分母／加總口徑（例如隱藏列是否納入、空值與 `0` 區分、`合計` 列以 `continue` 跳過）。
3. 執行橫向逐列與縱向分頁對平，產出 `reconciled: bool` 與具體 `mismatch_details`（限制前 20 筆）。
4. 若為跨期比較，計算 Volume / Rate / Mix 拆解；若需傳票檢核，確認總借方 ＝ 總貸方且不含雇主提撥污染個人薪資基準。

## When to Skip（不適用場景）
- 單純調整 React UI、CSS 版面、或無對帳邏輯的前端元件美化。

## ⚠️ Gotchas (避坑指南)
- **切勿拿聚合數字猜個別差異**：總金額偶然對平不代表沒錯（常見一正一負互相抵銷），務必做列級 Cross-footing 驗證。
- **個資不可進審查日誌或終端輸出**：對帳報告在日誌／測試輸出僅列異常筆數、原因碼、儲存格座標與金額差額，嚴禁印出真實員工姓名與完整薪資明細。
- **勿用動態容差掩蓋運算進位 bug**：先查明進位規則（無條件捨去／四捨五入／銀行家進位）再驗證，絕不隨意把容差放寬到 10 元以上。
