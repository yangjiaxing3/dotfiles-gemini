# Critical Stress Test

結構性紅隊與第一性原理審計。優先真相，不優先同意。不給鼓勵、不扮演多個人格，一次交一份能切開弱前提的審計。

跟 `/multi-agent-mode` 的關係：Phase B 的五維（髒資料、併發、時間、介接、效能）只打**程式方案**。本技能打**業務命題**（錢、人、對手、該不該做）。兩者並列，不互相取代。策略或產品決策在 Phase A 草案出來後、Phase C 拍板前跑完本技能；Phase C 必須回應第 4 節點出的自身盲點。純修 bug、單檔、不花資源的改動不要套這份。

## When to Use

- 商業策略、定價、B2B 合作、營運流程。
- 新架構、產品功能、行銷活動。
- 使用者要 stress test、挑戰假設、找盲點、唱反調。
- 即將投入資金、人力或工程，需要上線前審計。

## Steps

依序做完五節。省略寒暄、稱讚與開場。

### 1. 隱藏假設與第一性原理

寫出 2 到 3 個「計畫要成功就必須為真、但沒講出口」的前提。

- 拿掉產業慣例，看經濟或技術事實。
- 點出邏輯跳躍、跟先前說法矛盾、或量不到的指標。
- 指出這套邏輯的單一故障點。

### 2. 事前驗屍

假設六個月後這計畫徹底失敗。倒推 3 個最可能根因，各自對上：

- **單位經濟與隱藏成本：** 毛利被壓縮、獲客成本爆掉、沒計價的營運overhead。
- **執行與人：** 靠現場訓練、店端不照做、SOP 在真實班表裡垮掉。
- **外部與對手摩擦：** 合作方不對齊、法規、使用者行為不買帳。

### 3. 低成本路徑

挑戰資源強度。提出用約 20% 成本或複雜度拿到約 80% 價值的做法。

- 用人訓的地方改成腳本、護欄或自助。
- 拿掉中間層與過度功能。
- 給可執行的反提案，不給抽象建議。

### 4. 自我審計

立刻審計第 1–3 節自己的反提案。

- 至少一個關鍵盲點、邊界案例，或自己建議裡的錯誤假設。
- 寫明在什麼資料或市場條件下，使用者原方案其實比反提案好。

### 5. 高壓追問

用 2 到 3 個非修辭問句收尾，逼使用者為核心命題辯護或把假設量化，才能往下做。

## ⚠️ Gotchas (避坑指南)

- **零討好：** 禁止「這是個好的開始，不過…」「或許我們可以考慮…」。直接講結構缺陷。
- **具體：** 禁止教科書風險（「競爭可能加劇」）。每一刀都要錨在這家公司的現金、班表、資料口徑或技術限制。
- **單一聲音：** 不要再角色扮演一組顧問。一份審計。
- **跟程式紅隊分開：** 不要用本技能取代髒資料／併發／時區／介接／效能五維；那五維仍由 multi-agent Phase B 負責。
