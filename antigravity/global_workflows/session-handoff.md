# 上下文交接工作流 (Session Handoff)

當使用者提及「交接」、「收工」、「結束」、「handoff」、「/session-handoff」，或準備結束當前開發會話時，啟動此工作流。

本工作流有兩個模式：**收工模式（Wrap-Up）** 和 **接班模式（Resume）**。

---

## 🔍 模式判斷

收到觸發訊號後，先判斷使用者意圖：

| 訊號關鍵字 | 模式 | 說明 |
|-----------|------|------|
| 收工、結束、休息、handoff、交接、wrap up | **收工模式** | 生成/更新交接文件 |
| 接班、恢復、繼續、resume、讀取交接 | **接班模式** | 讀取交接文件恢復記憶 |
| 開工、開始新會話 | **接班模式** | 讀取交接文件 + 確認當前狀態 |

---

## Mode A: 🔴 收工模式 (Wrap-Up)

**觸發時機**：開發會話即將結束時。

### 步驟 1：掃描本次會話工作範圍

回顧本次對話中所有的操作，收集以下資訊：

- **修改過的檔案清單**：列出每個被 create/edit 的檔案
- **執行過的指令**：列出關鍵的 terminal 指令及其結果
- **做出的架構決策**：記錄任何設計抉擇及其理由
- **發現的問題或地雷**：記錄 debug 過程中學到的教訓
- **未完成的任務**：識別已開始但未完成的工作

### 步驟 2：更新 SESSION-HANDOFF.md

在**專案根目錄**找到或建立 `SESSION-HANDOFF.md`，按以下結構更新：

```markdown
# SESSION-HANDOFF.md — AI Agent 交接文件

> **用途**：此文件供 AI 開發代理在新會話中快速恢復專案狀態。
> **更新時機**：每次開發會話結束時由 AI 自動更新。
> **最後更新**：[YYYY-MM-DD HH:mm (UTC+8)]

---

## 🎯 目前的目標（Current Objective）
[正在開發的高階功能，1-2 句話描述]

---

## ✅ 已完成的工作（Completed Work）

### 最近一次開發週期（[日期]）

#### [模組/層級名稱]
- **[具體動作]**：[做了什麼] → 影響的檔案：`path/to/file`
- ...

---

## 🔜 下一步行動（Next Steps）

### 高優先
1. `[ ]` [任務描述]
2. `[ ]` [任務描述]

### 中優先
3. `[ ]` [任務描述]

### 低優先
4. `[ ]` [任務描述]

---

## ⚠️ 發現的地雷與決策（Discovered Gotchas）

### 🔴 嚴重
- **問題**：[描述]
- **後果**：[造成什麼影響]
- **解法**：[如何解決/避免]

### 🟡 注意
- [描述及解法]

### 🟢 架構決策
- [決策內容及理由]

---

## 📁 關鍵檔案索引
| 檔案 | 用途 |
|------|------|
| `path/to/file` | [說明] |

---

## 🔧 開發環境資訊
| 項目 | 值 |
|------|-----|
| 後端 Port | [port] |
| 前端 Port | [port] |
| 測試框架 | [framework] |
| 資料庫 | [type + path] |
```

### 步驟 3：檢查 README.md 是否需要同步更新

掃描本次會話的變更，判斷是否需要更新 `README.md`：

| 變更類型 | 是否更新 README |
|----------|----------------|
| 新增功能模組 | ✅ 必須更新功能總覽 |
| 新增 API 端點 | ✅ 必須更新 API 列表 |
| 修改啟動方式 | ✅ 必須更新快速啟動 |
| Bug 修復 | ❌ 不需要 |
| 重構（不改外部行為）| ❌ 不需要 |
| 新增依賴 | ✅ 更新技術架構或安裝指引 |

若需更新，執行最小化的增量更新（只改對應的章節，不重寫整份檔案）。

### 步驟 4：向使用者確認

輸出簡短摘要：

```
📋 交接文件已更新：SESSION-HANDOFF.md
📝 README.md：[已更新 / 無需更新]

本次記錄：
- ✅ 完成 N 項工作
- 🔜 下一步 N 項待辦
- ⚠️ N 個地雷/決策
```

**停止條件**：使用者確認收到後結束。

## Mode B: 🟢 接班模式 (Resume)

**觸發時機**：新會話開始時，或使用者要求恢復上次進度。

### 步驟 1：讀取交接文件

```
讀取順序（全部必讀）：
1. 專案根目錄/SESSION-HANDOFF.md  → 恢復開發狀態
2. 專案根目錄/GEMINI.md            → 載入 AI 操作規則
3. 專案根目錄/README.md            → 建立專案全局認知
```

### 步驟 2：驗證環境現狀

快速執行非破壞性的環境檢查：

```bash
# 確認 git 狀態
git status --short

# 確認最近提交
git log --oneline -5

# 確認後端是否在運行
curl -s http://localhost:8000/health 2>$null || echo "Backend not running"

# 確認前端是否在運行  
curl -s http://localhost:5173 2>$null | Select-String "<title>" || echo "Frontend not running"
```

### 步驟 3：向使用者彙報

以結構化格式彙報恢復狀態：

```markdown
## 🔄 上下文已恢復

**專案**：[專案名稱]
**上次會話**：[日期]
**目前目標**：[從 SESSION-HANDOFF.md 讀取]

### 環境狀態
| 服務 | 狀態 |
|------|------|
| 後端 API | ✅ 運行中 / ❌ 未啟動 |
| 前端 UI | ✅ 運行中 / ❌ 未啟動 |
| Git | ✅ 乾淨 / ⚠️ 有未提交變更 |

### 待辦事項（從上次接續）
1. [最高優先任務]
2. [次高優先任務]

### 需注意的地雷
- ⚠️ [上次發現的關鍵問題]

**準備好了嗎？請告訴我要從哪個任務開始。**
```

**停止條件**：使用者指定要做的任務後，切換至正常開發模式。

## 📏 品質規則

### 交接文件的內容標準

1. **具體，不抽象**
   - ❌ `修改了前端元件`
   - ✅ `修改了 InventoryContext.tsx 第 45-67 行，新增 property_tag 欄位的 API 映射`

2. **記錄「為什麼」，不只是「什麼」**
   - ❌ `使用了 UTF-8 NoBOM 編碼`
   - ✅ `使用了 UTF-8 NoBOM 編碼，因為 PowerShell 的 Set-Content 會寫入 UTF-16 LE BOM 導致 esbuild 解析失敗`

3. **下一步要「可執行」**
   - ❌ `繼續做前端`
   - ✅ `執行 npx vitest 確認 TaggingAndMyTasksE2E.test.tsx 通過，然後修復 KanbanFilterTDD 中的 CustomSelect mock`

4. **地雷要「可防禦」**
   - ❌ `小心編碼問題`
   - ✅ `PowerShell 批量替換禁止使用 Set-Content，必須改用 [System.IO.File]::WriteAllText($path, $content, [System.Text.UTF8Encoding]::new($false))`

### 檔案大小控制

- `SESSION-HANDOFF.md` 不應超過 **300 行**
- 如果歷史記錄太長，只保留最近 **2 次開發週期**的詳細記錄，更早的歸檔到「已完成的工作」摘要

### 增量更新原則

- 每次收工只更新**有變動的區塊**，不重寫整份文件
- 「已完成的工作」區塊採用**堆疊式**：最新的開發週期放最前面
- 「下一步行動」區塊採用**替換式**：根據最新狀態完全重寫

---

## ⚠️ 反模式警告

| 反模式 | 為什麼有害 | 正確做法 |
|--------|-----------|---------|
| 把交接文件當日記寫流水帳 | AI 讀取時會被無關資訊淹沒 | 只記錄影響後續開發的關鍵資訊 |
| 交接文件中包含大段程式碼 | 浪費 context 視窗 | 用檔案路徑 + 行數引用 |
| 不記錄地雷和失敗 | AI 會重蹈覆轍 | 地雷區塊是最有價值的部分 |
| README.md 和交接文件混為一談 | 職責不清，兩邊都做不好 | 嚴格分離：README 給人看，交接文件給 AI 看 |
| 交接文件超過 300 行 | 恢復記憶的效率下降 | 歸檔舊記錄，只保留最近 2 個週期 |

## 🔗 與其他工作流的整合

| 情境 | 整合方式 |
|------|---------|
| 使用 `/multi-agent-mode` 完成複雜任務後 | Agent E 驗收通過後，自動觸發收工模式 |
| 使用 `/subagent-driven-development` 時 | 每完成一個 task，更新 SESSION-HANDOFF.md 的進度 |
| 使用 `/tdd-workflow` 時 | 將測試通過/失敗狀態記入「已完成的工作」 |
| 使用 `/boundary-sentinel` 時 | 如果發現越界操作，記入「地雷與決策」 |
