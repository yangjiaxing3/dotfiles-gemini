# [Correct-Pattern] `/eli5` × `/ponytail` × `README.md` 人機雙讀持久化工作法

## 📌 Context
適用於所有專案（Storeasy 家族、US3C NEXT 家族及未來專案）之：
1. **更新或撰寫 `README.md`**（人機雙讀標準）
2. **新功能說明、流程／SOP 教學、線上故障復盤**
3. **多 Agent 協作交接與 `/ponytail` 精簡後之對人報告**

---

## ❌ [Anti-Pattern 錯誤模式]
1. **更新 `README.md` 只寫給 AI 或工程師看**：滿篇模組術語與環境變數，沒有白話定位與圖解，非技術同仁或老闆看不懂系統做什麼。
2. **為了好懂而遺漏 Repo 真實架構與契約**：只寫行銷空話，卻漏掉目錄結構、啟動指令、跨庫依賴與紅線，導致新進 AI Agent 仍須重掃全庫。
3. **誤在演算法／契約層套用 `/eli5`**：在 3D 幾何、財務計價、IoT 校準或 API 欄位規格中用模糊類比取代精確定義。

---

## ✅ [Correct-Pattern 正確作法]

### 1. 更新 `README.md` 黃金雙層架構（AI 秒懂全庫 ＋ 人 30 秒看懂）
- **上半部（給人看：強制 `/eli5` ＋ `/diagram-design`）**：
  - 用 `/eli5` 四段式白話交代：**一句話這是什麼 → 生活類比 → 核心怎麼運作（2–4 步）→ 誰在用／主要入口在哪**，確保超級外行人在 30 秒內讀懂業務價值。
  - 搭配 `/diagram-design` 產出繁體中文視覺架構圖（`docs/diagrams/*-zhtw.png`，遵守 `nodes <= 9, edges <= 12`）。
- **下半部（給 AI／工程師看：全 Repo 架構導航）**：
  - 先透過 `graphify`／實讀專案確認真實狀況，精準列出：**技術棧、目錄地圖、本地啟動與測試指令、跨 Repo 契約與不可妥協禁區**（純 AI 規則與詳細流程另放 `AGENTS.md`，決策索引放 `DECISIONS.md`）。

### 2. `/ponytail` ＋ `/eli5` 多 Agent 協作分工
- **對內寫碼與審查走 `/ponytail`**：最小完整變更、保護核心演算法禁區、刪減 `> 15` 行走 `multi_model_gate.py` 會審，程式碼保持零贅肉。
- **對外說明與交接走 `/eli5`**：在 PR 摘要、功能發布說明、系統報錯原因或 `// shortcut:` 技術債盤點時，將真實技術結論翻譯成「對業務的影響、目前限制與建議選項」，保留檔名／API 原文以便工程追溯。
